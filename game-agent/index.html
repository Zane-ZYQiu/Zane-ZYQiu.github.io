#操作应该是实际

还没开始。

1拿到需求

「给游戏加上撤销 / 重做，钱要算对，存档不能丢。」

2读代码、改代码

怎么实现由 Agent 自己定，题目不提供参考答案。

3进游戏实际操作

像玩家一样点鼠标：建造、拆除、撤销、存档、读档。

4看结果是否正确

钱对不对？撤销后城市回去了吗？存档坏了没有？

难在哪里？

玩家点一下鼠标，地图、建筑朝向、余额和操作历史要一起变。只要有一样没同步，就会出现「钱扣了楼没盖」「撤销后钱没退」这类 bug。这些代码读起来往往没毛病，要进游戏玩才看得出来。

🗺️地图盖了什么
🧭朝向朝哪边
💰余额还剩多少钱
↩️历史能不能撤销

需求是什么

  1. 钱要算对：拆掉建筑退一半的钱；钱不够就不让建，什么都不变。
  2. 能撤销、能重做：楼和钱一起回到之前的样子，而且只退一次。
  3. 存档靠得住：读档能还原整座城市；坏掉的存档不能把现在的城市弄乱。
  4. 出错要说清楚：存不进去、磁盘满了，都要提示玩家，而且不能毁掉之前的好存档。
  5. 原来的玩法不能坏：相机、建筑、价格、示例地图都照常工作。

03钱算得对余额和画面一致…
04存档与预算读档还原城市…
05长历史连续 32 步可撤销…

07磁盘写满不留半截存档…
08界面可用按钮和提示正确…
